# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability that could expose credentials, private data, or enable unauthorized access. Until a private reporting address is published, contact the repository owner through an established private channel and include reproduction steps, affected versions, and impact. Do not include real credentials or scraped personal data.

## Supported version

Security fixes currently target the latest commit on the default branch. This pre-release project does not yet promise long-term support for older revisions.

## Scope boundaries

The project is designed for public-source research with no outreach, no personal-account login, and no access-control bypass. Reports that demonstrate a violation of those boundaries are especially useful.
